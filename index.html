I design and build complete, role-based web systems — the kind real offices, schools, and small businesses run their day-to-day on. My work spans civic tech (a full barangay e-government portal), ed-tech (an internship-tracking platform used across four user roles), field-service management (a home-service booking and dispatch platform branded HomeServe, spanning four roles), and consumer platforms (a PC game distribution site with its own software library and hardware checker).

I handle a system end to end: database design, authentication, security rules, and interface — usually with Firebase as the backend, and plain HTML, CSS Tailwind, and JavaScript on the front. No build step, by choice — it keeps the finished project fast, dependency-free, and easy for a client (or another developer) to maintain long after I hand it off.

01

Database design that holds up. I model real schemas before writing a line of UI — OJTTrack alone runs on a 15-collection Firestore schema with documented relationships, not an ad-hoc set of tables bolted on later.

02

Access control that's actually enforced. Every system I ship separates roles (admin, staff, resident, student…) with Firestore Security Rules — permissions live on the server side, not just hidden buttons in the UI.

03

Real workflows, not just CRUD. Sequential document control numbers issued through Firestore transactions, admin-gated password resets, approval queues for name changes, client-side PDF/ID generation — the small operational details that make a system usable by non-technical staff.

04

Ships as a static site. Firebase Hosting plus security rules is the entire backend — no server to patch or pay for, which keeps ongoing costs low for a barangay office, a school, or a small business.
